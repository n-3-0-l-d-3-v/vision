# Vision

Creative and ideation agent for the personal multi-agent developer
ecosystem. Built from `10x/docs/agents/vision.md` in the ecosystem's
umbrella repo -- read that for the design intent this implements, and
`10x/docs/phases/README.md` Phase 3 for why the full free creative
software stack (Ardour, LMMS, Krita, GIMP, Penpot, Blender, DaVinci
Resolve, etc.) is explicitly deferred and NOT assumed by anything here.

## What's actually built (v1)

Four things, all genuinely useful with **zero external creative-app
dependencies** -- none of them shell out to or assume any DAW/design/
video-editor tool is installed:

1. **Creative project scaffolding** (`vision/scaffold.py`, `vision new`)
   -- creates a standard folder structure (`assets/`, `exports/`,
   `drafts/`) plus a `project.md` file with YAML frontmatter (title,
   type, created date, status, sensitivity tier) under a configurable
   projects root (`$VISION_PROJECTS_ROOT`, default
   `~/Desktop/Neil/creative-projects`). Supports six categories:
   `music`, `design`, `video`, `photo`, `writing`, `game`.

2. **Excalidraw starter-file generation** (`vision/excalidraw.py`,
   `vision excalidraw`) -- produces a syntactically valid, openable
   blank `.excalidraw` scene file (plain JSON: `type`, `version`,
   `source`, `elements`, `appState`, `files`), matching the real schema
   Excalidraw's web app writes for a blank canvas. See the module
   docstring for the schema derivation. Validated structurally by tests
   (`tests/test_excalidraw.py`), not just "a file exists."

3. **Asset manifest / cataloging** (`vision/assets.py`, `vision assets`)
   -- walks a project's `assets/` and `exports/` folders (recursively)
   and produces a manifest (JSON or Markdown table): name, size, type
   (by extension), last-modified. Pure filesystem work, no app needed.

4. **Vault MOC integration** (`vision/vault.py`) -- every `vision new`
   writes a project map-of-content note to `vault/Vision/`, matching the
   pattern Ultron/Alfred/Wall-E already use for their own vault folders
   -- this repo owns a local `vault/Vision/` path; a future ecosystem
   bootstrap step is expected to symlink/mount it at the real shared
   vault. `vision/projects.py` (`vision list`) scans the projects root
   for `project.md` files to enumerate known projects.

### `--private` is real, not a no-op

Per `10x/docs/agents/vision.md`'s sensitivity-tier note ("`work` for
public creative projects, `private` per-project override"), `vision new
--private`:

- sets that project's `project.md` **and** vault MOC note frontmatter
  `sensitivity_tier: private` (default: `work`), and
- routes the vault MOC note to `vault/Vision/private/` instead of
  `vault/Vision/`, matching the ecosystem-wide `vault/private/` vs
  `vault/public/` split in `10x/docs/omniroute-privacy-spec.md`, scoped
  to Vision's own vault subtree.

`tests/test_vault.py` and `tests/test_cli.py::test_new_command_private_flag_routes_moc_to_private`
exercise both effects directly.

## Explicitly out of scope for v1 (and why)

- **Real DAW/Krita/GIMP/Blender/video-editor automation** -- none of
  that software is installed on this machine yet (Phase 3 of the
  ecosystem plan is deferred). Vision v1 does not shell out to, detect,
  or pretend to integrate with any of it. Project scaffolding is
  useful organizational structure regardless of which app the user
  later opens.
- **UI/UX critique** -- needs a real model call (an LLM actually looking
  at a design and giving feedback), which is Phase 5 (local AI
  foundation) territory, not built yet. Not stubbed with a fake
  "critique" that doesn't call anything.
- **Portfolio-website generation** -- that's Phase 7 (socials/presence),
  a separate, larger piece of work than this ticket's scope.

None of these are stubbed with fake implementations -- they're simply
not present.

## Package vs. command name

The importable package is `vision` (module `vision`, e.g.
`python -m vision`); the installed console script is also `vision`,
matching `agent.yaml`'s `entrypoint: vision` /
`health_check_command: vision --health`. The distribution name in
`pyproject.toml` is `vision-agent` (to avoid clashing with the unrelated
PyPI package `vision`, if this is ever published; unrelated to the
importable module name).

## `vault/` and git

`agent.yaml` declares `default_sensitivity_tier: work`. Unlike Wall-E's
vault notes (raw system telemetry) or Ultron's `pending/`/`approved/`
review-gated findings, Vision's vault MOC notes are per-project records
generated by `vision new` on this machine -- and some are `private`-tier
by design. Judgment call: the whole `vault/Vision/` tree (including
`vault/Vision/private/`) is gitignored by default, same spirit as
Wall-E's "don't commit generated-on-this-machine notes by default" call
-- committing private-tier notes by default would defeat the point of
the `--private` flag. `.gitkeep` files keep the directory skeleton
itself tracked so `vault/Vision/` and `vault/Vision/private/` exist
after a fresh clone.

## Install

```powershell
cd vision
pip install -e ".[dev]"
```

No sibling-repo layout assumption is needed for v1 (unlike Wall-E, which
reads sibling `agent.yaml` files) -- Vision v1 doesn't poll or depend on
any other agent. `pyyaml` is a **dev-only** dependency (used only by
`tests/test_agent_yaml.py` to parse `agent.yaml`); runtime frontmatter
parsing is hand-rolled in `vision/frontmatter.py` since `project.md`/MOC
frontmatter is always a flat string-keyed block, not general YAML.

## Usage

```powershell
# Scaffold a new project (default root: $VISION_PROJECTS_ROOT or
# ~/Desktop/Neil/creative-projects)
vision new demo-song --type music

# Same, marked private (routes the MOC note to vault/Vision/private/)
vision new secret-track --type music --private

# Generate a blank, schema-valid Excalidraw starter file
vision excalidraw demo-diagram
vision excalidraw demo-diagram --project "path/to/some-project"   # writes into <project>/assets/

# Catalog a project's assets/ and exports/ folders
vision assets "path/to/some-project"
vision assets "path/to/some-project" --format json

# List known creative projects
vision list
vision list --json

# Vision's own status (ecosystem agent.yaml contract's health_check_command)
vision --health
```

`vision new`'s exit code is `1` for an unknown `--type` or a project
name that already exists (never silently overwrites); `0` otherwise.
`vision --health` exits `1` if unhealthy (projects root's parent
unreachable, or the vault directory isn't writable), `0` otherwise.

## Test discipline

```powershell
cd vision
pip install -e ".[dev]"
python -m pytest -v
```

68 tests, all passing on this machine:

- **Scaffolding** (`tests/test_scaffold.py`) -- correct folder structure
  and valid `project.md` frontmatter for every one of the six
  `--type` values; rejects unknown types and empty names; refuses to
  clobber an existing project directory; `$VISION_PROJECTS_ROOT`
  override honored.
- **`--private` flag** (`tests/test_vault.py`,
  `tests/test_cli.py`) -- asserts the MOC note actually lands under
  `vault/Vision/private/` (not just that the flag is accepted) and that
  frontmatter `sensitivity_tier` is set correctly for both the private
  and default (`work`) cases.
- **Excalidraw generation** (`tests/test_excalidraw.py`) -- parses the
  generated file as JSON and asserts the real required top-level keys
  (`type`, `version`, `elements`, `appState`) and correct `type` value
  are present; rejects scenes missing required keys or with the wrong
  `type` value.
- **Asset manifest** (`tests/test_assets.py`) -- built against a scratch
  directory with dummy files across `assets/`, `exports/`, and `drafts/`
  (drafts intentionally excluded per the task's "assets/+exports/"
  scope); asserts name/size/type/modified are all correct, plus both
  JSON and Markdown output.
- **`vision list`** (`tests/test_projects.py`) -- enumerates multiple
  scaffolded projects (including a mix of private/work tier), skips
  non-project directories.
- **`agent.yaml` validity and `--health`** (`tests/test_agent_yaml.py`,
  `tests/test_cli.py`) -- all required ecosystem-contract fields present
  with a valid tier value; `--health` JSON shape and healthy/exit-code
  behavior.
